# Модель данных MGIMO-LMS

Сводка для задачи #2 от 16 ноября 2026. Источник — текущие SQLAlchemy-модели
`app/models/` и миграции `migrations/versions/`. Это описание реализованной схемы,
а не новое архитектурное решение. Первоначальный путь `0002-data-model.md` в Issue
устарел: номер 0002 занят решением об источнике расписания.

| Область | Таблицы и связи |
| --- | --- |
| Студенты и группы | `students.study_group_id → study_groups.id → faculties.id` через `study_groups.faculty_id`. Направление и специализация — поля группы и профиля студента, отдельной таблицы направлений нет. |
| Учётные записи | `users.student_id → students.id`, `users.teacher_id → teachers.id`; роли `student`, `staff`, `teacher`. Сотрудник представлен учётной записью с ролью `staff`. `auth_sessions.user_id → users.id`. |
| Расписание | `lessons` связаны с группами через `lesson_groups`, с преподавателями через `lesson_teachers`; `lesson_changes` хранит изменения, `lessons.moved_to_id` — ссылку на перенесённое занятие. `import_runs` хранит историю импорта. |
| Заявки | `certificate_requests.student_id → students.id`; тип и статусы хранятся в заявке, история — `certificate_request_events.request_id → certificate_requests.id`. Ответы студента — `student_replies`, файлы ответа — `reply_files`. |
| Успеваемость | `courses` связывает дисциплину `disciplines`, группу и преподавателя. Состав ведомости — `course_enrollments`; задания — `assessments`; баллы студента — `scores`; итоги и попытки сдачи — `final_grades`. |
| Уведомления | `announcements` хранит автора и адресатов объявлений; `notification_reads` — прочтения пользователя. События заявок и `grade_events` служат источниками автоматических уведомлений. |

Уникальность балла задаётся парой «задание + студент», итога — тройкой
«ведомость + студент + попытка». Внешние ключи описаны в моделях и миграциях.
Доступ к данным дополнительно ограничивается запросами сервисов по пользователю из сессии.

## Миграции и подтверждения

В изученной рабочей копии цепочка линейная: `0001` расписание → `0002` заявки →
`0003` бумажные статусы → `0004` вход → `0005` Telegram → `0006` календарь →
`0007` успеваемость → `0008` уведомления → `0009` адресаты объявлений.
В опубликованную `dev` также влит PR #35 с миграцией `0010` покрытия расписания;
она не меняет перечисленные основные связи. Дополнительные таблицы базы знаний,
уведомлений о документах и языка интерфейса предложены отдельно в PR ассистента;
в модель этой ветки они не включены.

Применение миграций и откаты проверялись в PR #29/#32/#35; текущее действие
не запускает миграции на рабочей базе и не является повторной приёмкой стенда.
Подробные решения: [успеваемость](decisions/0007-grades.md),
[уведомления](decisions/0009-notifications.md), [архитектура](decisions/0001-architecture.md).
