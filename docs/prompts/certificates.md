# Справки и взаимодействие с деканатом

## 2026-11-05 — модель взаимодействия с деканатом (Pyrus)

- **Кто ставил:** Legpopov.
- **Промпт:** «Давай подумаем над взаимодействием со стороны деканата. В конкретном случае
  разберём получение справок. Вероятно, у них система типа 1С или/и Pyrus, где они формируют
  заявки на справки, проходят согласования, меняют статус готовности. Нужно заложить идею
  этого взаимодействия в наш продукт».
- **Интервью (скилл grillme), около 10 вопросов:** откуда знание о системах деканата
  (догадка по опыту капитана в другом вузе) → источник правды (Pyrus — статус, 1С — данные) →
  конфликт со своим кабинетом сотрудника из 0001 (берём настоящий Pyrus) → 1С (опыта нет,
  её роль играет наша БД) → что видит студент (упрощённые статусы + «нужна информация» с
  комментарием) → как отвечает (текст + файл) → подпись (синий прямоугольник) → кто делает PDF
  (наш бэкенд) → синхронизация (вебхук + сверка) → доступ жюри (тестовые логины в Pyrus).
- **Что сделал ИИ (Claude Code):** провёл интервью, нашёл противоречие с решением 0001
  (кабинет сотрудника, в который сотрудник с Pyrus не пойдёт), поискал условия тарифов Pyrus
  (официальной страницы в поиске не нашлось, агрегаторы указывают бесплатный тариф),
  записал решение [0003](../decisions/0003-dean-office-pyrus.md), пометил 0001 и README.
- **С первого раза:** структура цикла заявки и статусов.
- **Пришлось переделать:**
  - ИИ предложил QR-код «для проверки подлинности работодателем». Капитан отклонил: лишний
    сценарий, хватит имитации подписи синим прямоугольником;
  - ИИ записал доступность API на бесплатном тарифе как «не проверено». Капитан поправил:
    API Pyrus он уже использовал в работе, вебхуки и API на бесплатном тарифе работают.
- **Не сделано:** код интеграции, настройка формы в Pyrus, шаблон PDF.

## 2026-11-05 — серверная часть интеграции с Pyrus

- **Кто ставил:** Legpopov.
- **Промпт:** «Да, начинай» — реализация решения 0003. Работа велась в отдельной сессии
  Claude Code: пользователь переключился на другую задачу, план передан целиком.
- **Что сделал ИИ (Claude Code):** через субагента прочитал документацию Pyrus API v4
  (авторизация, задачи, комментарии, файлы, боты, лимиты) и опирался на неё, а не на память;
  написал модели и миграцию 0002, клиент Pyrus, вывод статуса из задачи, сервис заявок с
  очередью отправки, генерацию PDF, вебхук с проверкой подписи, фоновую сверку, CLI,
  поддельный Pyrus и 12 тестов; отрисовал PDF и проверил его глазами.
- **С первого раза:** модели, миграция (autogenerate, применяется и откатывается),
  клиент, сервис — все тесты зелёные на первом прогоне.
- **Пришлось переделать:** первый тест вебхука (на синхронном `TestClient`) проверял только
  коды ответа, а не то, что фоновая задача обновила заявку; к тому же `TestClient` крутит свой
  event loop, отдельный от БД и клиента теста. Заметил ИИ на самопроверке, переписал на
  `httpx.ASGITransport` (тот же loop) и добавил проверку итогового статуса и PDF.
- **Решено по ходу:** открытые вопросы 0003 — статус из поля «Статус для студента»,
  студент видит только поле «Сообщение студенту».
- **Документация Pyrus противоречива** в описании подписи вебхука (текст: «добавьте ключ
  к телу», код примера: HMAC-SHA1 тела ключом бота). Сделано по коду примера; проверить на
  живом боте.
- **Не сделано:** экраны ЛК (ждут входа и сессий), настройка формы и бота в живом Pyrus,
  seed тестовых студентов, отправка уведомлений в Telegram из таймлайна.

## 2026-11-05 — бумажный оригинал и срок скачивания (по образцу РАНХиГС)

- **Кто ставил:** Legpopov — через соседнюю сессию Claude Code, которая разбирала ЛК РАНХиГС
  ([разбор](../research/ranepa-lk.md)). Одобрение капитана: «Да, перенеси».
- **Промпт (пересказ):** добавить второй, бумажный статус; бумагу можно запросить только после
  скачивания электронной справки; у PDF срок скачивания; запрос бумаги — комментарием в задачу
  Pyrus через очередь, закрытую задачу переоткрыть; бумажный статус ведёт деканат полем формы,
  выбор в списке через API не пишем; вид «только бумага».
- **Что сделал ИИ (Claude Code):** поля и миграция 0003 (с `server_default` для старых заявок,
  проверено на заявке, созданной до миграции), чтение поля «Бумажный оригинал», очередь запросов
  бумаги с переоткрытием задачи, срок скачивания `CERT_DOWNLOAD_DAYS`, вид «Справка о периоде
  обучения (для перевода)» только на бумаге, подписи статусов для будущего экрана, 4 новых теста.
- **С первого раза:** все тесты зелёные на первом прогоне.
- **Решено по ходу:**
  - после «Готова» электронный статус больше не меняется — иначе переоткрытие задачи ради бумаги
    откатило бы её в «На согласовании» (запасной вывод статуса из закрытости задачи);
  - бумагу можно запросить только один раз (из «нет»): после «не востребован» поле формы осталось
    бы старым и перебило бы новый запрос;
  - у вида «только на бумаге» отдельного комментария нет — запрос уходит полем «Выдача» вместе
    с задачей.
- **Не сделано:** экраны ЛК, кнопка «В моей справке есть ошибка» и защита от дублей из разбора
  РАНХиГС — не входили в задачу.

## 2026-11-05 — сколько почт завести в Pyrus

- **Кто ставил:** Legpopov.
- **Промпт:** «Делаем блок пайруса, давай подумаем сколько временных почт нам надо (по одной почте
  на роль работника деканата, декана, директора института и т.п.)… Потом попросим тебя через
  браузер в пайрусе настроить эту организацию».
- **Как шло:** сократовское интервью (скилл grillme), 5 вопросов. Капитан сначала хотел почту
  на каждую роль, затем сам вернулся к упрощению: один «сотрудник всех деканатов».
- **Итог:** одна временная почта (обычный бесплатный ящик) + почта капитана как админ; маршрут
  из двух шагов на одного сотрудника; один общий логин на всё жюри. Записано в 0003,
  раздел «Учётные записи Pyrus».
- **Пришлось пояснить:** как жюри может сменить пароль (из профиля, зная текущий; сброс через
  «Забыли пароль?» им недоступен — письмо уходит в наш ящик).
- **Не сделано:** настройка организации в Pyrus через браузер — следующий шаг.

## 2026-11-05 — настройка организации Pyrus через браузер

- **Кто ставил:** Legpopov.
- **Промпт:** «все открыто в браузере, можешь заходить, нужно настроить прошлые согласования уже
  готовые задней датой для видимости, и настроить путь между пользователями». Потом добавил:
  «пока создаются такие согласования, так же проверить связь с ботом, ЛК студента и кабинетом в Pyrus».
- **Уточнили:** поставить задаче в Pyrus прошлую дату нельзя, поэтому делаем «просто готовые заявки».
  Они должны быть видны и деканату, и студенту, значит создаются через ЛК.
- **Что сделал ИИ (Claude Code + Claude in Chrome):** форма «Справка» (14 полей), линейный маршрут
  из двух этапов на «Декана Хахатонова», бот-вебхук на стенд, бот добавлен наблюдателем.
- **Что пришлось переделывать:** шаблон формы. Перетаскивание из палитры давало лишние текстовые
  поля, подробности в ai-mistakes.md.
- **Не сделано ИИ намеренно:** перенос секретного ключа бота в `.env` (это делает человек).
- **Не сделано:** выкладка правки кода, сквозная проверка ЛК → Pyrus → Telegram, демо-заявки.
