# Проверка масштаба конкурсного стенда

## 2026-11-17 — команды наполнения и архитектура для 10К+ студентов

- Кто ставил: Legpopov. Ключевой запрос: проверить команды из переписки и решения
  архитектуры для 10К+ студентов и 1К+ сотрудников.
- Уточнения: аудит без внедрения; вымышленные данные, вход у всех, десятки
  одновременных пользователей; ориентир 800 преподавателей с занятиями и 200
  остальных сотрудников; расписание всех групп из РУЗ, размер групп можно увеличить.
- С первого раза по актуальным исходникам обнаружены отсутствующий флаг
  `--include-unscheduled`, неиспользуемые настройки bootstrap/scope, неизвестные
  массовые пароли, пропуск уже заполненных групп и отсутствие массовых входов сотрудников.
- Результат: `docs/process/scale-audit-2026-11-17.md`, read-only SQL
  `scripts/audit_scale.sql`; предложения по приоритетам и проверке приёмки.
- Что пришлось уточнить: речь о командах терминала, а не командах людей;
  большой объём записей недостаточен — требуется доступ каждому аккаунту.
- Ограничения: сервер не изменяли и не проверяли, CLI изучен по argparse;
  локальная `.venv` ссылается на недоступный Python. Нагрузочные испытания не проводились.
  Архитектурные предложения не оформлены как принятые ADR: решения о внедрении нет.

## 2026-11-17 — реализация большого стенда и контекста преподавателя

- Кто ставил: Legpopov. Промпт: «Проводи необходимые изменения, коммить и пушь»;
  дополнение — преподавательский LLM должен иметь данные своих студентов,
  требуется подтвердить загрузку.
- Реализовано: отдельный scale CLI с проверкой перед записью, дополнение групп без
  сброса, массовые синтетические входы, проверка доступности паролей и покрытия,
  SQL-область преподавателя, индикатор загрузки, ограниченные argon2-потоки,
  освобождение соединения БД перед проверкой пароля, read-only нагрузочный CLI.
- С первого раза прошли проверки дополнения группы и фильтрации передаваемых
  данных. Что переделали: тестовый helper входа студента оказался неприменим
  после смены роли на teacher; вход в тесте выполнен до смены роли. Визуальный
  фикстурный стенд первоначально запросил 100 студентов у единственной группы,
  корректно сработал лимит 40; для UI-проверки выбран набор из 40+1 студентов.
- Важная корректировка по измерению: не удерживать соединение БД во время
  вычисления argon2; ограничение потоков удерживается до завершения вычисления,
  даже если HTTP-запрос отменён. После смены пароля во время проверки старый
  пароль не должен приниматься: повторная сверка хэша перед созданием сессии.
- Проверка сервера read-only: 26/2/1 аккаунтов, 92 преподавателя, 1987 занятий;
  последние импорты failed, HTTPS РУЗ имеет истёкший сертификат. Полное наполнение
  не выполнено и не заявлено; TLS не ослаблялся. Изменения сервера не производились.
- ADR 0020 и инструкция `docs/contest-scale.md` описывают границы решения.
- Уточнение пользователя: «я не просил блок свои студенты. Убери его».
  Блок удалён; контекст своих студентов определяется автоматически на сервере,
  без выбора в интерфейсе. Неудачный вариант сохранён в скриншоте с суффиксом
  `rejected`; финальный экран проверен на 360 px без горизонтального переполнения.
- Проверка полного периода усилена: отдельная транзакционная квитанция импорта
  группы и миграция 0013; короткое окно не подтверждает загрузку семестра.
- Последующее прямое указание пользователя: продолжать импорт несмотря на истёкший
  сертификат. Добавлено ограниченное исключение `RUZ_VERIFY_TLS=false` только для
  HTTPS ruz.mgimo.ru:443 без редиректов. По умолчанию и для других сервисов проверка
  включена. Реальный пробный запрос из контейнера дал 200 и 38 факультетов.
- Перед выкладкой сверена схема сервера `0013_merge`; изменения перенесены на
  актуальную dev `5256a7a` в отдельной рабочей копии. Сохранены порты/адаптеры
  ассистента и доменное разрешение оценок; использована существующая таблица
  покрытия из миграции 0010 вместо новой миграции. Полный прогон: 255 passed,
  4 skipped (отдельная PostgreSQL-БД не задана), 2 subtests passed.
- Отдельно проверена граница большого преподавательского контекста: превышение
  лимита записей всегда добавляет ограничение выборки и статус partial, даже если
  LLM выбрала одну корректную оценку. Целевой прогон преподавательских тестов — 4 passed.
- Для большой БД область преподавателя строится объединением прямых назначений
  и заранее выбранных пар «группа–дисциплина», без коррелированного перебора всех
  ведомостей. Проверен второй преподаватель из РУЗ, не являющийся владельцем
  ведомости; доступ к чужому предмету закрыт. Преподавательские и scale-тесты — 8 passed.
- Живой GigaChat вернул intent=request и был отклонён схемой. Для маршрутизации
  и выбора фактов включён response_schema; ID ограничены фактически загруженными
  записями. 26 целевых тестов прошли. Реальный вызов с исправлением разобрал Plan
  и Selection, вернул partial с двумя фактами, без вывода оценок в диагностический лог.
