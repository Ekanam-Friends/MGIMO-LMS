## 2026-11-05 — импорт расписания из РУЗ в БД

- **Кто ставил:** Legpopov.
- **Промпт:** «Да, пиши импорт» — продолжение предыдущей записи.
- **Интервью (скилл grillme), 4 вопроса:** куда класть данные → сразу PostgreSQL с каркасом;
  какие группы → весь вуз; период и скорость → весь семестр, по одному запросу с паузой 1 с;
  фиксировать ли изменения → да, журнал изменений.
- **Что сделал ИИ (Claude Code):** нашёл `/api/dictionary/groups` (все 1534 группы одним
  запросом) и `/api/dictionary/lecturers`; замерил объём (семестр одной группы ~3 МБ, ~3 с);
  посмотрел диффер в Ikanam-schedule и перенёс его правила на РУЗ, где у занятия есть
  стабильный `lessonOid`. Написал каркас `app/` (настройки, БД, модели), миграцию Alembic,
  клиент РУЗ, белый список полей, генератор вымышленных ФИО, импортёр с журналом изменений,
  CLI, 22 теста на поддельном сервере РУЗ.
- **С первого раза:** клиент, нормализация, миграция (autogenerate), CLI.
- **Пришлось переделать:**
  - вставка занятия падала на NOT NULL `last_seen_at` — поймали тесты;
  - при сбое группы посередине не откатывались кэш преподавателей и счётчики в памяти —
    заметил ИИ на самопроверке до запуска тестов;
  - аудит БД после живого импорта нашёл вымышленную фамилию, совпавшую с фамилией реального
    преподавателя → добавлен стоп-лист фамилий из справочника РУЗ.
- **Проверка:** живой импорт 5 групп за семестр (3233 занятия), два повторных — без ложных
  изменений; аудит БД по всем 3424 преподавателям — ни ФИО, ни email.
- **Не сделано:** полный прогон по всему вузу, проверка на PostgreSQL.
- **Итог:** раздел «Реализация» в [0002](../decisions/0002-schedule-source.md).

  «добавлено» (см. ai-mistakes) — полный импорт остановлен и перезапущен с чистой БД.
- **Итог полного прогона:** 1534/1534 групп за 40 минут без ошибок, 193 865 занятий,

- **Доступ к БД:** в DBeaver пользователя добавлено подключение к `local.db` (только чтение).

## 2026-11-16 — расписание на стенде заполняется само (догрузка ботом)

- **Кто ставил:** raxlin4ik; PR по просьбе капитана («создай PR, я посмотрю, подредачу и волью»).
- **Промпт:** «мне сказали, что с открытого источника расписание тянется через вебхук. Посмотри
  код… сначала документацию… если расписание само сразу не забивается, то надо как-то исправить,
  потом продумай, как наш нейрослоп учеников закинуть в БД».
- **Что выяснил ИИ:** вебхука для расписания нет (вебхук в проекте — от Pyrus, для справок);
  расписание тянут ручной `import_ruz` и бот, который обновляет только группы студентов с
  Telegram. На стенде (проверка запросом только на чтение) — 2 группы, 1987 занятий, поэтому
  генератор успеваемости дал 24 студента.
- **Что сделал ИИ (Claude Code):** `BOT_BOOTSTRAP_GROUPS` — бот при старте догружает весь
  семестр недостающих групп (курсы 1–6) до N, уже загруженные не трогает; `BOT_IMPORT_SCOPE` —
  обновлять группы студентов с Telegram или всех студентов. По умолчанию выключено. Решение
  [0011](../decisions/0011-schedule-bootstrap.md), раздел в deploy.md, 4 теста на поддельном РУЗ.
- **С первого раза:** код и тесты (4 из 4 зелёные на первом прогоне).
- **Пришлось переделать:** чтобы подменить РУЗ в тестах, функции догрузки понадобился параметр
  `transport` (по умолчанию пустой).
