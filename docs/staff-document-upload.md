# База знаний: загрузка документа работником

Работник открывает «База знаний» на главной деканата, выбирает PDF, указывает
название, ссылку на публичный оригинал mgimo.ru и обозначение редакции.
После подтверждения публичности нажимает «Загрузить документ». Обработка
запускается автоматически; «Обновить список» показывает её результат.

| Состояние | Что означает |
| --- | --- |
| В очереди | Оригинал сохранён в БД, обработка ожидает запуска |
| Обрабатывается | Извлекается текст и готовится обновление корпуса |
| Доступен ассистенту | Фрагменты добавлены в опубликованный индекс |
| Нужна проверка | Например, у скана нет текста: требуется OCR и исправленный PDF |
| Ошибка обработки | Причина показана в карточке, доступна повторная обработка |

Справочный снимок используется в рамках текущих правил свежести и применимости
корпуса; статус публикации не подтверждает даты действия нормативного акта.
Форма поддерживает PDF до 10 МБ и 100 страниц, без пароля, с текстовым слоем.
Ввод ссылки не запускает её скачивание. Загружаемый файл работник сверяет сам.
Индексирование не обращается к платным эмбеддингам; выдержки могут передаваться
GigaChat при последующих вопросах студентов, как и остальные публичные источники.

Повторный файл распознаётся по SHA-256. Неуспешную загрузку можно исправить
новым PDF по той же ссылке. Замена уже опубликованного источника новой редакцией
оставлена администратору, чтобы не скрывать историю и не создавать противоречия.
Последние 100 загрузок видны всем вошедшим сотрудникам с ролью `staff`;
студенты и преподаватели доступа к этому разделу не получают.
Базовые документы, подготовленные через CLI, не являются загрузками работников
и в этом списке не показаны; они сохраняются при дополнении индекса.

## Классы и методы

Дополнение: после обработки работник может предложить адресатов с помощью ИИ
и подтвердить уведомления в кабинетах студентов и Telegram. Подробный сценарий —
[уведомления о документе](document-notifications.md).

- `KnowledgeDocument` — новая ORM-модель оригинала и задания обработки.
- `DocumentMetadata` — Pydantic-класс проверки названия, URL, редакции и подтверждения публичности.
- `upload_document(db, actor, filename, data, metadata)` — функция сервиса;
  возвращает объект документа и признак создания/исправления загрузки.
- `DocumentProcessor.process_one()` — обрабатывает одно задание.
- `DocumentProcessor.run()` — восстанавливает очередь и последовательно выполняет задания.

Работник по-прежнему представлен `User(role="staff")`. В предметной UML
`StaffProfile.upload_document(...)` обозначает действие работника; переносить
БД и индексирование в объект его профиля не требуется.

## Подключение

1. Применить миграции: `python -m alembic upgrade head`. Для этой ветки новая
   вершина — `0010_documents`; родитель — `0009`.
2. Установить зависимости `pip install '.[rag]'` либо пересобрать Docker-образ.
3. Обеспечить постоянное доступное на запись хранилище `RAG_CORPUS_DIR`.
   Существующее серверное монтирование `/opt/mgimo-lms/data:/data` подходит,
   если пользователь контейнера uid 1000 имеет право записи. Для нового
   контейнера без тома индекс пропадёт при его пересоздании.
4. Использовать один процесс web и `RAG_USE_EMBEDDINGS=false`.
   Во время отдельной публикации CLI обработчик web следует остановить.

Не публикуйте непроверенные закрытые документы: это публичный корпус внешнего
GigaChat, а не локальный режим работы с внутренними актами.
Подробности: [решение 0016](decisions/0016-staff-document-upload.md).

## Проверка

Автоматические сценарии — `tests/test_document_upload.py`: роли и CSRF,
валидация, повторы, поиск по новому тексту, сохранность рабочего корпуса,
ошибки PDF, исправленная загрузка, потоковый лимит, сканы и восстановление очереди.
Ручная проверка проведена на отдельной SQLite-БД с вымышленными учётками,
без ключа GigaChat и обращения к продовым данным. В браузере выполнены вход
работника, загрузка тестового PDF и получение статуса публикации на 360 px;
затем вход студента и проверка 404 для `/d/documents`.
