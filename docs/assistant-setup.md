# Подключение ассистента по положениям

Реализация находится в `app/assistant/`, интерфейс — `/s/assistant`.
Сначала подготовьте корпус и ключ. Без настройки показывается состояние недоступности,
а не выдуманные ответы. 21 ноября 2026 на production проверены конкретные сценарии
с настоящим GigaChat-2-Max; результаты и пределы проверки описаны в
[журнале выкладки](process/pr45-production-2026-11-21.md). Полнота корпуса,
действие редакций и точность всего OCR этой проверкой не подтверждаются.

## Зависимости и конфигурация

```powershell
python -m pip install -e ".[dev,rag]"
```

`rag` нужен только для импорта PDF; для запуска чата PDF-парсер не используется.
Для сканов установите Tesseract с `rus+eng` и укажите путь при импорте.
Ключ внесите в серверный `.env`, не в HTML, JS, журнал команд или git:

```dotenv
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=<из личного кабинета GigaChat>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Max
GIGACHAT_CA_BUNDLE=/data/ca/russian-trusted-ca.pem
RAG_CORPUS_DIR=/data/regulations
RAG_TOP_K=5
RAG_MAX_SOURCE_AGE_DAYS=30
RAG_REQUESTS_PER_MINUTE=6
LLM_EMBEDDING_MODEL=
```

Scope и модель выбираются по доступу конкретного проекта. Для векторов укажите
доступную модель GigaChat embeddings и используйте `--embed` при подготовке.
Без модели эмбеддингов работает BM25. При смене embedding-модели индекс надо
пересоздать: несовпадение запрещает смешивать вектора.

Официальные документы: [OAuth](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token),
[генерация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat),
[эмбеддинги](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-embeddings),
[сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).
Клиент использует `https://api.giga.chat/v1` и OAuth
`https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Проверка сертификатов не отключается.

## Корпус: сначала проверка, затем включение

Скопируйте публичный PDF рядом с `manifest.json`. Пример метаданных ниже — шаблон,
не настоящее положение. Не ставьте `reviewed_public=true` автоматически для любого
файла с сайта: исключите документы с персональными данными и проверьте редакцию.

```json
[
  {
    "file": "regulation.pdf",
    "document_id": "academic-leave",
    "revision": "номер приказа и редакция",
    "title": "Название публичного положения",
    "source_url": "https://mgimo.ru/путь-к-настоящему-документу.pdf",
    "document_date": "2026-01-01",
    "effective_from": "2026-02-01",
    "effective_to": null,
    "checked_at": "2026-11-15",
    "downloaded_at": "2026-11-15",
    "reviewed_public": false,
    "reviewed_sha256": "",
    "reviewed_text_sha256": ""
  }
]
```

Даты заменяются фактическими. `effective_to` — первый день, когда редакция уже
не действует. Дата скачивания не заменяет дату вступления в силу. Если редакция
имеет обратную силу, укажите подтверждённое основание в `retroactive_basis`.

1. Получите текст для сверки:

   ```powershell
   python -m app.assistant.ingest manifest.json --out review --preview
   # Если PDF — скан:
   python -m app.assistant.ingest manifest.json --out review --preview --tesseract "C:\путь\tesseract.exe"
   ```

   Команда печатает хэши оригинала и извлечённого текста, сохраняет
   `extracted-review.jsonl` с `reviewed_public=false` и не меняет рабочий индекс.
2. Сверьте пункты с оригиналом, включая отрицания, сноски, условия, сроки и границы
   страниц. Внесите оба проверенных хэша и `reviewed_public=true` в манифест.
   Ошибки OCR надо исправить в подготовленном корпусе либо повторить корректное
   распознавание. Текущий CLI не является редактором OCR.
3. Создайте индекс теми же параметрами извлечения:

   ```powershell
   python -m app.assistant.ingest manifest.json --out data/regulations
   # Для подготовленного гибридного режима:
   python -m app.assistant.ingest manifest.json --out data/regulations --embed
   ```

   На сканах повторите `--tesseract`. Проверяется совпадение текста с утверждённым
   хэшем. Новый снимок проверяется целиком, затем `chunks.jsonl` заменяется атомарно.
   CLI не открывает пользовательские URL и не скачивает документы.

Фрагмент длиннее 6000 знаков или короткий неоднозначный блок требует ручной
подготовки JSONL, автоматического усечения нет. Разбиение не восстанавливает
ссылки и условия между страницами; после импорта нужна сверка полноты.
Хэш подтверждает неизменность проверенного текста, а не юридическую актуальность.

## Проверка перед стендом

```powershell
python -m pytest -q
```

Войти вымышленным студентом, открыть ассистента, задать вопрос по настоящему
публичному пункту, сверить выдержку, страницу, поля и редакцию. Повторить для
исторической даты, неоднозначности и отсутствия ответа. Сетевой сбой должен
показывать ошибку, не ближайший регламент. Тесты с заглушками не измеряют качество LLM.

Сохранить контрольный набор, снимок корпуса, модель, ответы, задержки и стоимость.
Отдельно оценить релевантность поиска, точность отказа и полноту процедуры вручную.
Минимальная обязательная регрессия: академический отпуск не должен выдавать
трудовой отпуск или переход на бесплатное обучение.

История страницы живёт до её перезагрузки. Ассистент не оформляет справки и не
передаёт профили или оценки провайдеру. Регулярное скрытие ФИО/email/телефона
снижает случайную передачу, но не распознаёт все категории личных данных.
На стенде используйте HTTPS и `COOKIE_SECURE=true`. При нескольких воркерах
замените ограничитель частоты на общий Redis/БД или ограничение прокси.
