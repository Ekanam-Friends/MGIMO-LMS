## Порядок запуска

Команды выполняются на Linux-сервере в `/opt/mgimo-lms`, после выкладки этой версии.
`git push` сам по себе не обновляет работающие контейнеры. Перед записью в БД
сделать и проверить бэкап по [инструкции аудита](process/scale-audit-2026-11-17.md);
хранить не более трёх последних успешных копий. Не запускать две подготовки одновременно.

```bash
docker compose exec -T web python -m app.schedule.import_ruz --full
docker compose exec -T db psql -U lms -d lms -c "SELECT id, finished_at, status, groups_total, groups_ok, groups_failed FROM import_runs ORDER BY id DESC LIMIT 3;"
docker compose exec -T web python -m app.seed
docker compose exec -T web python -m app.generate.scale --check
```

Первый скрипт импортирует справочники и расписание всех доступных групп за семестр,
заменяя ФИО преподавателей вымышленными. Он не генерирует студентов.
При частичном импорте код завершения может быть 0 — сверять отчёт и покрытие групп.
`scale --check` ничего не меняет: код 1 означает, что критерий ещё не выполнен.

После проверки результата импорта и бэкапа:

```bash
docker compose exec -T web python -m app.generate.scale --apply --demo-access
docker compose exec -T web python -m app.generate.scale --check
```

В `.env` нужен непустой `DEMO_PASSWORD`, уже используемый `app.seed`. Флаг
`--demo-access` явно разрешает применить его к сгенерированным аккаунтам.
После изменения `.env` пересоздать web, чтобы его окружение обновилось; приложение
не перечитывает переменные контейнера на каждый CLI-запуск.

- Студенты: `st<id_группы>-<номер>`; ранее созданные сгенерированные аккаунты тоже
  получают этот демо-пароль. Учётки `student1`, `student2` сохраняются из seed.
- Преподаватели: `demo-teacher-<id>`; существующие преподавательские аккаунты не дублируются.
- Другие сотрудники: `demo-staff-<номер>`; `dean` из seed учитывается в общей численности.

Генератор выбирает все пригодные группы со свежим расписанием, дополняет их до
`ceil(10000 / число_групп)` сгенерированных студентов (не более 40 на группу).
Итог может превышать 10К из-за округления, демо-учёток и уже существующих групп.
Старые оценки не сбрасываются. Языковая подгруппа и история нового студента в
наполненной группе берутся из синтетического учебного профиля одногруппника.
При недостатке групп/преподавателей команда останавливается с понятной ошибкой.
Если это выявлено после генерации ведомостей, уже успешно обработанные группы
сохраняются; повторный запуск безопасен и не дублирует их.

Для обновления расписания всех доступных групп без Telegram:

```bash
docker compose exec -T web python -m app.schedule.import_ruz
```

Это окно −7…+35 дней. Периодическое выполнение настраивать отдельным заданием
с защитой от наложения запусков. `BOT_BOOTSTRAP_GROUPS` и флаг
`--include-unscheduled` для этой процедуры не нужны. `--reset` не использовать.

По прямому указанию пользователя добавлено исключение для истёкшего сертификата РУЗ:
в серверном `.env` можно явно задать `RUZ_VERIFY_TLS=false`, затем пересоздать web/bot.
По умолчанию значение true. Исключение принимается только для HTTPS-хоста
`ruz.mgimo.ru` на порту 443, без перехода по редиректам. Проверка других сервисов
не меняется. В этом режиме подлинность TLS-сертификата РУЗ не проверяется;
после обновления сертификата вернуть true. Пробный запрос в этом режиме дал
HTTP 200 и 38 факультетов.

## Проверка преподавательского ассистента

1. Войти преподавателем, открыть «ИИ-ассистент», начать обычную беседу.
   Дополнительного блока выбора студентов нет: область доступа определяется
   сервером по учётной записи преподавателя.
2. Задать вопрос об успеваемости своих студентов и подтвердить разрешение в беседе.
   В GigaChat передаются только свои дисциплины, без полной зачётки и заявок на справки.
   Студенты обозначены номерами, ФИО не передаются. Контекст включает количества
   загруженных записей и время последнего наблюдения своих занятий при импорте.
3. Подстановка чужого id через API возвращает 404. После изменения зачислений
   доступ пересчитывается даже у открытой беседы.

Число оценок 0 означает отсутствие оценок в доступном снимке, а не доказательство
неуспеваемости. Дата импорта и доступность каждой категории показаны отдельно.

## Проверка нагрузки

```bash
docker compose exec -T web python -m app.generate.loadcheck --users 50 --rounds 3
```

URL по умолчанию берётся из `PUBLIC_BASE_URL`. Для Secure-cookie нужен HTTPS.
Запуск использует смешанные роли, отдельные cookie-сессии, параллельный вход и
чтение страниц успеваемости/курсов/сотрудника. Выводятся p95/max и HTTP-ошибки;
код 0 подтверждает отсутствие зарегистрированных ошибок, но не соблюдение SLA.
Этот прогон не сохраняет оценки, не создаёт справки и не отправляет внешние сообщения.
Массовые LLM-запросы проверять отдельно с учётом квот и оплаты провайдера.

Для подтверждения полного семестра используется существующая миграция `0010`
(ветка расписания, включена в серверную `0013_merge`):
успешный непустой импорт группы сохраняет период и id запуска в отдельной
таблице. Одного свежего занятия или короткого окна недостаточно. Короткое обновление
не стирает подтверждение полного периода; старые данные без такой записи требуют
повторного полного импорта после восстановления РУЗ. Готовность требует свежего
подтверждения полного семестра не старше семи дней.

Локальный HTTP-прогон на 41 студенте, 4 преподавателях и 2 сотрудниках: 40
одновременных сессий, 120 чтений страниц, без HTTP-ошибок. В отдельном запуске
без pytest p95 входа 9,011 с, p95 страниц 2,303 с. Это характеристика локального
маленького набора на SQLite, не обещание для VPS или 11К+ аккаунтов; предложенная
цель p95 страниц до 2 с этим запуском не подтверждена. Запись оценок под нагрузкой
и массовые LLM-вызовы не проверялись.
