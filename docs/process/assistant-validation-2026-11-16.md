## Реальный сервер и GigaChat

OAuth и `/models` вернули 200, генерация `GigaChat-2` — 200. `EmbeddingsGigaR`,
`Embeddings-2`, `Embeddings`, `GigaEmbeddings-3B-2025-09` вернули 402. Эти запросы
не дали векторов. По решению Legpopov платные эмбеддинги не подключались,
`RAG_USE_EMBEDDINGS=false`. Локальная модель генерации/эмбеддингов не устанавливалась.

До переключения основного web проверена отдельная сборка на том же сервере
с реальной вымышленной учёткой `student1` и настоящим API:

| Сценарий | Результат | Время наблюдения |
| --- | --- | --- |
| Расписание на завтра | answer, записи кабинета | около 1 с |
| Статусы своих заявок | answer, 2 записи | около 0,5 с |
| Оценки до согласия | consent_required, 0 записей | около 0,2 с |
| Разрешение и оценки | answer, записи кабинета | около 1,1 с |
| Материальная помощь | partial, выдержка из положения, страница 12 | около 2,5 с |

Это отдельные наблюдения, не нагрузочный тест и не гарантия задержки.
Для расписания предоставляются занятия группы с указанными подгруппами.
Для длинных списков показываются выбранные записи; полный список — в разделе кабинета.

После выкладки проверены HTTPS-вход (200), новая страница и реальный вопрос
«Как студенту получить материальную помощь?» в браузере production. Получен
частичный ответ с выдержкой, фрагментом 102 положения о стипендиальном обеспечении,
страницей 12 и явной оговоркой о непроверенных действии редакции и OCR.
