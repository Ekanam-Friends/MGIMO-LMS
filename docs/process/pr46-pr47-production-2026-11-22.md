Дата: 22 ноября 2026, МСК. Постановщик: Legpopov.

Задача: применить исправления ревью, исправить Ingress, проверить на production
до слияния в dev. Пользователь уточнил: рабочий сайт и dev; main не обновлять.

## Исправления

- #46: отправки инвалидации сериализованы asyncio.Lock; каждому ожидающему сбросу
  присвоен токен. Успешный ответ Redis удаляет только подтверждённую версию,
  сохраняя более поздний сброс того же имени. Регрессионный тест моделирует два
  коммита и ошибку второй отправки.
- #47: административный kubeconfig 0600, без рекомендации публичного чтения;
  proxy-read-timeout ingress-nginx 90 с при дедлайне ассистента 70 с;
  три CACHE_*_TTL в ConfigMap и реестре config.
- При Linux-приёмке дополнительно исправлен CRLF реестра env-keys.txt:
  LF в .gitattributes и удаление CR перед сравнением awk. Shell-тест использует
  отдельную копию реестра в CRLF и не меняет исходную рабочую папку.
- Конфликты с текущим dev разрешены с сохранением обеих записей документации,
  fakeredis и PyYAML; interview остаётся исключённым из образа и git archive.

Образ: `mgimo-lms-web:pr46-pr47-4416f32`, image id

## Ограничения

Это функциональная проверка, а не нагрузочная приёмка и не проверка аварийного
переключения. Прямой клиентский поток Telegram не проверялся отправкой сообщений;
проверен запуск polling. Качество OCR и актуальность нормативных актов не принимались.
Production продолжает работать через Compose и Caddy; Kubernetes использовался
для отдельной живой проверки манифестов и Ingress.
