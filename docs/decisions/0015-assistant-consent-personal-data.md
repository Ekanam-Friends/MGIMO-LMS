# 0015. Личные данные и разрешения в беседе ассистента

Дата: 16 ноября 2026. Основание — интервью с Legpopov.
Статус: реализовано и развёрнуто; [проверки](../process/assistant-validation-2026-11-16.md).

## Решение

Ассистент отвечает по публичным положениям, расписанию группы текущего студента,
его оценкам и статусам заявок. Создание и изменение заявок в этот этап не входят.
До начала беседы студент явно подтверждает, что ИИ может ошибаться и важные
ответы нужно проверять. До подтверждения сервер не принимает вопросы.

Оценки читаются из БД только после отдельного разрешения, которое чат запрашивает
при первом вопросе об успеваемости. Разрешение действует на одну беседу.
Очистка диалога отзывает его; новая беседа вновь требует разрешения.
Браузер не может разрешить доступ простым полем `grades_allowed` в вопросе.
Подтверждение принимается отдельным POST после того, как сервер запросил его.

Разрешения хранятся в памяти одного процесса uvicorn, как и текущие лимиты
ассистента. Случайный идентификатор беседы привязан к серверной сессии входа,
не сохраняется в localStorage и живёт максимум два часа. Перезапуск процесса,
закрытие/перезагрузка вкладки или очистка беседы требуют новых разрешений.
Хранилище ограничено 2000 активных бесед. Для нескольких процессов/реплик
приложения понадобится общее серверное хранилище; реплика PostgreSQL сама по
себе не делает разрешения распределёнными. Сообщения и личные данные здесь не хранятся.

## Получение и вывод данных

GigaChat определяет необходимые разделы по вопросу и истории вопросов.
Этот план не предоставляет прав: без разрешения ветка оценок возвращает
запрос согласия до выполнения запросов БД. Идентификатор студента берётся
исключительно из сессии; значения от модели и браузера не используются для доступа.
Оценки/заявки фильтруются по этому студенту; расписание — через его группу в SQL.
Отдельная подгруппа студента в расписании пока не определяется: она явно указана
в найденных занятиях, вывод называется расписанием группы.

В API передаются только необходимые записи: предмет, баллы и даты, либо время
и место занятия, либо вид/номер/статус заявки и время синхронизации. ФИО,
контакты, цель справки, сообщения деканата, PDF справок и комментарии преподавателя
не передаются. Модель выбирает ID записей; текст и ссылки формирует сервер
из фактических данных. Неизвестные ID отклоняются, произвольный пересказ оценок
не показывается. Текущий снимок кабинета не выдаётся за историческое состояние.

RAG сохраняет проверку публичности и редакций, цитаты и отдельный аудит применимости.
Векторный канал ищет по всему разрешённому корпусу, затем объединяется с BM25
через RRF. Веса вынесены в конфигурацию; равные веса — исходная настройка,
а не доказанный оптимум. Изменение весов не требует новых эмбеддингов.

Фактическое развёртывание 16 ноября использует BM25. Все четыре проверенные
embedding-модели GigaChat вернули HTTP 402; Legpopov отказался от платных
эмбеддингов. `RAG_USE_EMBEDDINGS=false` задан в окружении и по умолчанию.
Веса семантического канала в этом режиме не применяются и не объявляются настроенными.

Для 27 уже загруженных PDF введён явный статус `snapshot`: неизвестные даты
документа и действия допустимы как `null`, такие фрагменты не участвуют в
историческом поиске и всегда дают частичный справочный ответ с предупреждением
о непроверенной актуальности и OCR. Проверенные редакции по-прежнему требуют
полных метаданных. Проверка свежести снимка использует дату исходного манифеста,
а не дату OCR. Прямой запрос оригинала с сервера вернул защитный HTML, не PDF;
он не считается подтверждением актуальности. Номера пунктов из OCR не выдаются
за проверенные: в ссылке показываются фрагмент и диапазон страниц.

## Граница полностью локального варианта

Поиск по всем доступным сотруднику локальным НПА с локальной генерацией и
эмбеддингами — возможное расширение вне задач хакатона. Локальная модель
в MGIMO-LMS не развёрнута; текущий API-режим не является полностью локальным.
Нужны отдельные права на документы, поддержка внутренних источников, проверка
ресурсов и качества; ограничения описаны в плане индексирования.
