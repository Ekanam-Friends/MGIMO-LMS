# 0012. Ассистент по публичным положениям через GigaChat API

Дата: 15 ноября 2026. Статус: реализовано локально; приёмка живого API и корпуса предстоит.
Дополняет 0007 о подготовке корпуса и уточняет выбор провайдера из требований 0011.
Основание: запрос Legpopov — изучить конкурентов, перенести полезные приёмы в
ИИ-ассистента MGIMO-LMS, использовать исключительно GigaChat API и публичные документы.

## Решение

1. Только серверный GigaChat. Пустой/иной `LLM_PROVIDER` отключает ассистента.
   OAuth-токен кэшируется до истечения, после 401 — одно обновление. TLS включён,
   CA добавляется к системному хранилищу. Redirect провайдера не выполняется.
2. Нет инструментов LLM, SQL, профиля, оценок и действий со справками. В модель
   отправляются вопрос, до четырёх предыдущих вопросов и найденные публичные выдержки.
3. Корпус — проверенный `chunks.jsonl`. Метаданные включают источник, исходный SHA-256,
   документ/редакцию, дату документа, начало/конец действия, скачивание и проверку.
   Обратная сила требует основания. Неизвестная редакция, просроченная проверка,
   пересечение редакций и непубличный файл не используются как актуальные нормы.
4. Поиск: BM25 по документам → BM25 по пунктам, лексический фильтр релевантности.
   Опциональные векторы GigaChat с совпадающей моделью сливаются через RRF.
   Без `LLM_EMBEDDING_MODEL` работает только BM25; это явно отдельный режим.
5. Модель выбирает ID исходных выдержек и их порядок. Сервер подставляет исходный
   текст и URL; поле кто/срок/бланк принимается только как подстрока источника.
   Второй запрос GigaChat проверяет применимость и полноту. Отброшенные шаги
   приводят к частичному ответу. Отдельный аудит не равен независимой экспертной оценке.
6. Ошибка/таймаут модели никогда не маскируется отказом или ближайшим документом.
   Пользователь видит разные состояния: answer, partial, clarify, not_found,
   error, unavailable, busy.
7. Чат доступен после входа; POST требует CSRF. История хранится только в памяти
   открытой страницы, без общих кэшей и localStorage. Ответы и страница — no-store.
   Перезагрузка страницы очищает историю. Произвольный HTML не рендерится.
8. До 2000 символов в вопросе, 4 вопроса истории, 24 КБ на тело запроса,
   6 запросов в минуту на учётку, 1 активный на учётку и 2 на процесс. Общий
   серверный дедлайн — 70 секунд. Лимиты частоты в памяти рассчитаны на один процесс.
9. Импорт PDF — административный CLI, без сетевого скачивания. Сначала preview,
   ручная сверка текста и OCR, затем подтверждение двух хэшей и публикация индекса.
   Студенческой загрузки файлов и URL в первой версии нет.

## Цена и ограничения

Обычный ответ — два chat-запроса: выбор и аудит; гибридный режим добавляет эмбеддинг
вопроса. OAuth запрашивается при обновлении токена. Вопрос без кандидатов отсекается
до обращения к генератору. Денежная стоимость и реальная задержка ещё не измерены.

Формат намеренно ближе к исходному тексту, чем свободный пересказ. Длинные пункты
могут делать ответ многословным. Подсветка относится к извлечённой выдержке в чате,
PDF открывается на странице; подсветки координат непосредственно в PDF пока нет.
DOCX/XLSX, автоматическое обновление корпуса, исторический архив и полнота
официального корпуса не обещаются одним наличием кода.

Дальнейшие изменения выбираются по контрольному набору и измерениям. Отдельный
набор проверки качества требуется до объявления ассистента готовым к использованию.
