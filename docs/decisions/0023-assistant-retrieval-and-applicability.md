# 0023. Поиск нормативных выдержек и проверка применимости

Дата: 2026-11-17. Статус: принято.

## Причина

На опубликованном снимке f3fc4f2d3f2b (862 выдержки, 27 документов) воспроизведены
четыре пользовательских вопроса. Разговорный вопрос об отчислении выбирал ВКР,
длинный вопрос о болезни отбрасывался порогом 50% совпадений, пустой выбор модели
становился ошибкой валидации. Общая тема документа не доказывает применимость нормы:
экзамен нельзя подставлять вместо контрольной точки текущего контроля.

## Решение

- Поиск BM25 выполняется по всем допустимым выдержкам, без предварительного
  ограничения двумя актами и без порога, зависящего от длины разговорного вопроса.
  Выбор редакций, проверка публичности и свежести остаются до поиска.
- Планировщик выделяет короткую поисковую фразу. В генерацию и аудит поступает
  исходный вопрос; поисковая фраза не заменяет намерение пользователя.
- Сценарий получает до 3 × RAG_TOP_K кандидатов. Чистая функция `evidence_context`
  добавляет соседние выдержки того же документа и редакции в исходном порядке,
  даже если разные документы перемешаны в индексе. Контекст наиболее релевантного
  кандидата имеет приоритет. Сериализованный список sources ограничен 32 000
  символов, ни один текст не обрезается. Файловый адаптер и провайдер остаются за портами.
- Выбор цитат и аудит используют JSON Schema с допустимыми ID. Проверка на сервере
  сохраняется: реальный ID, дословные поля, отдельная проверка применимости.
  Пустой выбор повторяется один раз; повторный пустой выбор не становится выдуманным ответом.
  Схема используется по [контракту GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).
  Планировщик сохраняет обычный JSON и строгую проверку Pydantic: в живом API
  сочетание длинного промпта маршрутизации с response_format давало пустой content.
- Аудит сначала сопоставляет процедуру и основания в reason, затем принимает ID.
  Reason не публикуется как нормативный ответ и не заменяет цитату.
- Модель по умолчанию — GigaChat-2-Max, уже используемая в проекте для перевода.
  На одинаковом корпусе GigaChat-2 ошибочно отклоняла прямую норму Устава и
  выбирала посторонние условия. Max в контрольном прогоне выбрала Устав 004817-40,
  условия отпуска 000631-18, перечислила темы и отказала в неподтверждённом освобождении
  от контрольной точки. Это четыре smoke-сценария, а не полная оценка качества.
- Вопрос о возможностях возвращает состав активного корпуса (до 30 названий),
  без чтения персональных фактов и без согласия на оценки.

## Ограничения

Снимок не объявляется действующей редакцией; нормативные ответы остаются partial
со ссылками и предупреждением о датах/OCR. Pending-review OCR не публикуется автоматически.
Загрузка сотрудником PDF с текстовым слоем автоматически пополняет индекс, скан
получает needs_review; OCR для загрузок через кабинет не добавлен этим изменением.
Эмбеддинги и платный пакет не включаются.
