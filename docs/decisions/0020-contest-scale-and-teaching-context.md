# 0020. Большой синтетический стенд и учебные данные преподавателя

Дата: 17 ноября 2026. Статус: принято для конкурсного стенда.
Источник: Legpopov, аудит и последующее поручение реализовать изменения, коммит и push.

## Требование

10К+ студентов, ориентир 800 преподавателей с занятиями и 200 остальных сотрудников;
вход доступен каждому, одновременно работают десятки пользователей. Расписание
групп берётся из РУЗ, ФИО и успеваемость вымышленные. Преподавательский ассистент
должен получать данные своих студентов с проверяемым составом и временем снимка.

## Решение

- Сохраняем монолит FastAPI, PostgreSQL, серверные сессии, Compose и один web-процесс.
  Горизонтальное масштабирование требует отдельного выноса фоновых задач и состояния бесед.
- `python -m app.generate.scale` по умолчанию только проверяет готовность; запись
  требует `--apply --demo-access` и `DEMO_PASSWORD`. Первичный импорт выполняется
  отдельно, без зависимости от Telegram. Неуспешная приёмка даёт ненулевой код.
- Группы дополняются до целевого размера без reset. Новые синтетические студенты
  в уже наполненной группе получают копию вымышленного учебного профиля
  сгенерированного одногруппника. Старые записи, оценки и ручные правки не меняются.
- Для конкурсного набора явно применяется общий демо-пароль из окружения. В БД
  хранится argon2-хэш; пароли и хэши в отчёт не выводятся. Для массового набора
  один хэш переиспользуется — это сознательное ограничение исключительно синтетического
  стенда, не механизм регистрации реальных пользователей. Ранее созданные чужие
  аккаунты и их пароли не перезаписываются; их несовпадение с общим демо-паролем
  явно проваливает проверку общей доступности.
- Преподаватель получает доступ к студенту по зачислению в свою дисциплину:
  ведущий ведомости либо преподаватель соответствующей дисциплины и группы в
  импортированном расписании текущего учебного года. Это учитывает несколько
  преподавателей одной дисциплины без смены ведущего ведомости и права редактирования.
- Поиск, начало беседы, проверка загрузки и каждый вопрос проверяют эту область
  SQL-запросом. Демо-флаг не открывает преподавателю чужих студентов. В LLM-контекст
  идут только доступные дисциплины, их баллы/итоги и свои занятия группы.
  Заявки на справки и оценки чужих дисциплин не читаются и не передаются.
- Контекст преподавателя формируется автоматически без нового блока выбора в UI.
  Метаданные загруженных данных включаются в контекст, отдельный read-only endpoint
  позволяет проверить выбранного своего студента. Отсутствие записи не трактуется
  как отсутствие события; отсутствие подтверждённого импорта показано явно.
- Argon2 проверяется вне event loop, не более четырёх вычислений одновременно.
  При отмене HTTP-запроса поток сохраняет слот до фактического завершения работы.
  Выделенная транзакция чтения `/login` закрывается перед проверкой пароля, затем
  хэш повторно сверяется в БД, чтобы не принять пароль, сменившийся во время проверки.

## Ограничения и приёмка

`scale --check` проверяет численность, связи аккаунтов, расписание используемых групп
не старше семи дней и реальные зачисления преподавателей, а также общий демо-пароль
по каждому уникальному хэшу (до 16 уникальных хэшей; иначе готовность не подтверждается).
Это проверка данных и учётных записей, а не пропускной способности сервера.
Период каждой группы подтверждается отдельной квитанцией `group_schedule_coverage`
в транзакции импорта, используется существующая миграция `0010` из `0013_merge`.
Новая миграция не нужна. Короткий импорт не считается
доказательством загрузки всего семестра и не уничтожает прежнюю квитанцию.

На 17 ноября 2026 проверка HTTPS из работающего web-контейнера показывает
`CERTIFICATE_VERIFY_FAILED: certificate has expired` у РУЗ. Первоначально массовая
приёмка была остановлена. Затем пользователь прямо потребовал продолжить несмотря
на истёкший сертификат. Добавлено явное исключение `RUZ_VERIFY_TLS=false` только
для HTTPS `ruz.mgimo.ru:443`, без редиректов; другие сервисы сохраняют проверку.
По умолчанию TLS проверяется. Исключение отключает проверку подлинности сертификата
именно РУЗ; после обновления сертификата настройку следует вернуть в true.
Это не отменяет проверку фактического покрытия групп и данных после импорта.
