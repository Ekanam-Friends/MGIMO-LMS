# 0022. Модель чтения карточек справок без изменения UX

Дата: 17 ноября 2026. Статус: принято.
Постановщик — Legpopov: исправить замечания #37, сохранив все фичи и UX/UI главных.

`app/certificates/dashboard.py` готовит неизменяемый RequestCard для отображения.
Он содержит подписи, цвет, акцент и доступную дополнительную строку; шаблон
не получает ORM-заявку, PDF или сервис для самостоятельного вычисления статуса.
Правило истечения срока и подписи бумажной выдачи берутся из существующего сервиса;
короткие подписи и цвета соответствуют принятому дизайну #37.

Сценарий чтения ограничивает SQL текущим студентом из сессии и тремя последними
заявками. Сортировка «дата, затем id по убыванию» сохранена. Наличие PDF проверяется
выражением SQL, содержимое PDF отложено и не загружается для карточки.
Время снимка общее для трёх карточек, чтобы срок не оценивался по-разному внутри
одного ответа. Ссылки на детали и заказ, пустое состояние и оформление сохранены.

Это application-модель чтения, а не изменение доменной сущности или схемы БД.
Остальные сценарии справок, календаря, успеваемости, преподавателя и деканата
используют прежние сервисы. CSS и обработчики функций #37 не меняются.

Граница приёмки: идентичные снимки до/после на синтетических данных для трёх ролей
на 360 и 1440 px, проверка фич и тесты состояний/фильтрации. Это не доказывает
идентичность всех возможных данных, браузеров и языков; полнота локализации не
объявляется завершённой этой задачей.
