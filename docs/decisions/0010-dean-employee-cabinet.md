# 0010. Кабинет деканата = кабинет сотрудника + адресные объявления

Дата: 2026-11-10. Статус: принято, реализовано. Дополняет [0008](0008-teacher-employee-cabinet.md) и [0009](0009-notifications.md).
Автор задачи: Legpopov. Код и документ писал Claude Code.

## Контекст

По решению 0009 у сотрудника деканата было два пункта меню («Объявления» и «Профиль»). Задача:
деканат должен полностью повторять кабинет сотрудника (как у преподавателя, решение 0008) и
дополнительно уметь писать уведомления студенту, группе и потоку.

## Решения

| Вопрос | Решение |
|--------|---------|
| Общая часть «сотрудника» | У деканата те же главная (`/d/home`), «Сервисы Академии» (`/d/services`, тот же шаблон, что у преподавателя), «Кадровые сервисы» (`HR_MENU` общий с преподавателем), профиль с карточкой сотрудника |
| Своё у деканата | Группа меню «Деканат» → «Объявления»; плитка на главной |
| Что такое «поток» | Программа + курс: `students.speciality` + `students.course`. Отдельной таблицы потоков нет, миграция добавляет только поля в `announcements` |
| Адресаты | Все / факультет / **поток** / группа / **студент**. Миграция 0009: `program`, `course`, `student_id` |
| Выбор студента | Поиск по ФИО (HTMX, `/d/students/search`), только для роли staff; показывает ФИО, группу и курс. Регистр кириллицы в SQLite не понижается, поэтому перебираются типичные написания, а не `lower()` |
| Кто видит | Лента студента по сессии: поток — совпали программа и курс, адресное — только `student_id` из сессии. Преподаватель адресные объявления не видит (как и раньше), а свои пишет только группам, у которых ведёт курс |
| Карточка сотрудника | Вымышленная, от id учётной записи (`staff_card`), без миграции |
| Колокольчик | У деканата по-прежнему нет: он автор, а не получатель |
