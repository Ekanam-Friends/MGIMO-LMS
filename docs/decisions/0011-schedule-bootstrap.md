# 0011. Расписание на стенде заполняется само: догрузка ботом при старте

Дата: 2026-11-16. Статус: предложено (PR), включается переменными окружения.
Автор задачи: raxlin4ik. Уточняет [0002](0002-schedule-source.md) и строку «Обновление
расписания» в [0005](0005-telegram-bot.md).

## Контекст

Расписание приходит не вебхуком: его тянут из открытого API РУЗ две вещи — ручная команда
`python -m app.schedule.import_ruz` и бот, который раз в `BOT_IMPORT_HOURS` перечитывает окно
−7…+35 дней **только по группам студентов с подключённым Telegram**. При выкладке на стенд
импортированы две демо-группы (docs/deploy.md), и бот их обновляет, но остальные 1532 группы
пусты. Из-за этого генератор успеваемости (решение 0007) создаёт на стенде 24 студента вместо
~3000, а у преподавателей в расписании только занятия демо-групп. Полный импорт никто не
запускает: это ручная команда на сервере.

## Решение

| Вопрос | Решение |
|--------|---------|
| Как заполнить пустую базу | Бот при старте проверяет, у скольких групп есть занятия. Если меньше `BOT_BOOTSTRAP_GROUPS`, грузит **весь семестр** недостающих групп (только курсы 1–6, без аспирантуры) тем же `ScheduleImporter`, что и CLI |
| Повторные старты | Уже загруженные группы не трогаются; когда групп хватает — один запрос к своей базе и ни одного к РУЗ |
| Пуши о «новых» занятиях | Не будет: импортёр не пишет в журнал `added` для группы, загружаемой впервые (правило из 0002) |
| Что обновлять потом | `BOT_IMPORT_SCOPE`: `linked` (как раньше) — группы студентов с Telegram; `students` — группы всех студентов в базе, в том числе сгенерированных |
| По умолчанию | Всё выключено: `BOT_BOOTSTRAP_GROUPS=0`, `BOT_IMPORT_SCOPE=linked` — поведение не меняется, пока капитан не включит |
| Нагрузка на РУЗ | Те же ограничения, что в 0002: `RUZ_CONCURRENCY=2`, пауза 0,5 с. 400 групп ≈ 10 минут один раз. `students` при ~250 группах — окно −7…+35 дней раз в 6 часов ≈ 3–4 минуты запросов |

Рекомендуемые значения для стенда: `BOT_BOOTSTRAP_GROUPS=400` (на 3000 студентов генератора
по 12 в группе нужно ~250 групп с расписанием; 400 — с запасом на группы без занятий) и
`BOT_IMPORT_SCOPE=linked` (сгенерированные студенты в кабинет не входят, их расписанию
достаточно снимка семестра).

## Почему не cron и не web

- Cron на сервере — ещё одна вещь вне репозитория и docker-compose, её легко забыть при
  переезде. Бот уже держит фоновые задачи и ходит в РУЗ.
- В web импорт не встраиваем: там один процесс uvicorn, и 10 минут запросов к РУЗ при старте
  ни к чему странице входа.

## Порядок на стенде

1. В серверном `.env`: `BOT_BOOTSTRAP_GROUPS=400`. Перезапустить бота
   (`docker compose up -d bot`). Через ~2 минуты после старта начнётся догрузка, в логах бота —
   «догружаю семестр ещё N групп», затем «догрузка расписания: ok».
2. После этого — генератор: `docker compose exec web python -m app.generate`.
