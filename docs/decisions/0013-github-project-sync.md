# 0013. Двусторонняя синхронизация Issues и Project

Дата: 16 ноября 2026. Статус: принято; полная автоматизация подготовлена, доступ не подключён.

## Контекст

Пользователь попросил добавить Issues в Project и обратно, включая синхронизацию статусов.
Выбраны преобразование черновиков в Issues и переоткрытие при переносе из Done.
Встроенные правила GitHub покрывают авто-добавление, закрытие и реакцию на переоткрытие Issue,
но не весь выбранный сценарий.

## Решение

Сохраняем встроенную автоматизацию. Дополняем её GitHub Actions с опросом раз в пять минут.
Источники — API GitHub, отдельной копии карточек или БД синхронизации нет. Скрипт использует
ID объектов и атомарное преобразование draft item в Issue, обходя все страницы выдачи.
При конфликте состояние выбирается по времени изменения поля Status и последнему событию
закрытия/переоткрытия Issue. Начальная установка Todo не переоткрывает закрытую задачу.
Архивные карточки и чужие репозитории не меняются.

Новый workflow по умолчанию выключен переменной. Пользователь отдельно подключит токен;
существующие локальные учётные данные в репозиторий и Actions не переносятся.
Условия включения и ограничения описаны в [инструкции](../project-sync.md).

## Последствия

Синхронизация не мгновенная, зависит от доступности Actions и API. Изменения, совершённые
одновременно с записью скрипта, не защищены общей транзакцией GitHub. Новые активные черновики
Project предназначены для Issues MGIMO-LMS; для посторонних заметок нужен другой Project.
При большом числе карточек опрос потребует пересмотра лимитов API и перехода к webhooks.
