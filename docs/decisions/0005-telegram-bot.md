# 0005. Telegram-бот: бесплатная часть ikanam_schedule_bot на данных кабинета

Дата: 5 ноября 2026. Статус: принято.
Источник: задача капитана «бот @Lms_university_ekanamfriends_bot должен уметь всё, что умеет
бесплатная версия ikanam_schedule_bot, только для МГИМО» и интервью (скилл grillme).

## Контекст

У команды есть рабочий бот расписания РАНХиГС — `ikanam_schedule_bot` (репозиторий
`lkanam-schedule`). Он сам ходит в чужой ЛК по логину и паролю студента, проходит антибот
через Playwright и сравнивает снимки расписания. В MGIMO-LMS кабинет свой: расписание уже
лежит в нашей БД, изменения уже пишет импорт РУЗ в журнал `lesson_changes`, а события заявок
на справки — в `certificate_request_events` с полем `notified_at` «для Telegram».

## Решения

| Вопрос | Решение |
|--------|---------|
| Как бот узнаёт студента | **Кнопка «Подключить Telegram» в профиле** → одноразовый код (живёт 15 минут, в БД — SHA-256) → `t.me/<бот>?start=<код>`. Пароль в бот не вводится вообще. Дальше студент определяется только по telegram id отправителя (`telegram_links`) |
| Откуда расписание | Из БД кабинета, та же функция `lessons_for`, что у экрана «Расписание». Слой РАНХиГС (клиент ЛК, Playwright, диффер снимков) не переносится |
| Код ikanam | Не копируем целиком, а переписываем на данные кабинета, сохраняя формат сообщений, экраны и решения (UTC в `.ics`, отмены со `STATUS:CANCELLED`, `SEQUENCE`, инструкции подписки по платформам, «не открывайте ссылку в браузере») |
| Объём | Вся бесплатная часть: сегодня/завтра/неделя с листанием, подписка календаря и файл `.ics`, утренняя сводка, пуши об изменениях, настройки, `/status`, `/logout`. Платный `/qr` (отметка на лекциях через СДО), донаты, статистика владельца — не переносятся |
| «Дедлайны СДО» | У МГИМО в прототипе нет СДО. Вместо них — **контрольные точки**: зачёты, экзамены и контрольные из расписания (`/exams`), напоминание за 1/3/7 дней. Плюс то, чего в ikanam не было, но есть в кабинете: **статусы справок** (`/certificates` и пуши) |
| Пуши об изменениях | Читаем `lesson_changes` по курсору `bot_cursors`. Первый запуск ставит курсор на конец журнала — историю не рассылаем. Пишем только о занятиях в ближайшие 21 день, по группам занятия |
| Пуши по справкам | Строки `certificate_request_events` с пустым `notified_at`; отметка ставится всем, даже без бота, чтобы после подключения не пришла вся история |
| Обновление расписания | Бот раз в `BOT_IMPORT_HOURS` (по умолчанию 6) перечитывает РУЗ, но только по группам подключённых студентов — РУЗ чужой сервер. Полный импорт остаётся ручной командой. **Уточнено в [0011](0011-schedule-bootstrap.md):** при `BOT_BOOTSTRAP_GROUPS` бот догружает семестр на пустую базу, `BOT_IMPORT_SCOPE=students` расширяет обновление на группы всех студентов |
| Лента календаря | Отдаёт web: `GET /feed/<токен>.ics` без входа (календари не умеют cookie), доступ — по секрету в адресе. Токен перевыпускается в боте; `/logout` и «Отключить» в профиле его убивают |
| Процесс | Отдельный контейнер `bot` в том же compose, тот же образ, long polling (публичный адрес не нужен). Миграции применяет `web`. Токен — только `TELEGRAM_BOT_TOKEN` в `.env` |
| Демонстрация пуша | `python -m app.bot.demo_change --login student1 [--cancel]` меняет ближайшее занятие и пишет запись в журнал, как импорт. Следующий импорт РУЗ вернёт настоящие данные |

## Безопасность

- Студент видит только своё: ни команда, ни кнопка не принимают id студента; в callback_data —
  только даты (не дальше года от сегодня) и значения настроек из белого списка.
- Код привязки одноразовый, новый код гасит прежние. Если тот же Telegram подключает другого
  студента, привязка переезжает (код выдан кабинетом после входа — это и есть подтверждение).
- Сотрудник без студенческой записи код получить не может (404).
