# 0007. Успеваемость и кабинет преподавателя

Дата: 2026-11-09. Статус: принято, реализовано (задачи #22, #7, #3).
Автор задачи: raxlin4ik. Код и документ писал Claude Code, постановка и проверка — человек.

## Контекст

Ядро кабинета требует раздел «Успеваемость»: оценки и зачёты, сессия, «как у меня дела».
Оценки должны откуда-то браться, поэтому нужна вторая сторона — кабинет преподавателя, где
ставятся баллы накопа, задаются домашние задания и выставляется итог в зачётку. Решение 0003
отказалось от своего кабинета сотрудника деканата (деканат живёт в Pyrus), но у преподавателя
своей системы в прототипе нет — для него кабинет делаем сами.

## Решения

| Вопрос | Решение |
|--------|---------|
| Единица учёта | **Курс = ведомость**: дисциплина × группа (или подгруппа) × семестр, один ведущий преподаватель. Таблица `courses` |
| Кто в ведомости | Явная запись `course_enrollments`, а не «вся группа»: языки в РУЗ идут подгруппами («английский первый», «испанский первый»), студент сидит в одной |
| Откуда курсы текущего семестра | **Из расписания РУЗ группы**: каждая дисциплина → курс; ведущий — преподаватель, у которого больше всего занятий по ней у группы (семинары весят вдвое — баллы ставит семинарист). Экзамен в расписании → форма контроля «экзамен». Так ФИО преподавателя в зачётке совпадает с расписанием |
| Прошлые семестры | В РУЗ их нет — дисциплины берутся из типового плана в `app/generate/curriculum.py` (составлен с ИИ, не повторяет реальный план МГИМО) |
| Шкала | Балльно-рейтинговая, 100 баллов. Экзамен и зачёт с оценкой: накоп до 60 + экзамен до 40, допуск от 30. Зачёт: всё 100 — текущий контроль, «зачтено» от 55. Итог: 85+ «отлично», 70+ «хорошо», 55+ «удовл.». Все пороги — в `app/grades/scale.py` |
| Накоп | Контрольные точки `assessments` (ДЗ, контрольная, работа на семинарах, эссе, рубежный контроль) с максимумом и сроком; баллы — `scores`, одна строка на пару «точка × студент», шаг полбалла |
| Итог | `final_grades` с номером попытки. Пока ведомость открыта — правится основная попытка; после «Закрыть ведомость» итог меняется только пересдачей (до 3 попыток) у тех, у кого последняя неудачна |
| Домашние задания | Это контрольная точка вида «ДЗ» с текстом задания и обязательным сроком. Студент видит текст и срок в «Скоро сдавать». Приём файлов — вне объёма (ДЗ сдаются в СДО) |
| Уведомления | Журнал `grade_events`: новое ДЗ, балл, итог. Лента «Новое в успеваемости» в кабинете; бот (решение 0005) и общий раздел уведомлений (#10) читают строки с пустым `notified_at`, как у справок |
| «Как у меня дела» | Процент считается **от возможного на сегодня**: только точки, срок которых прошёл или балл уже стоит. «Работа на семинарах» копится до конца семестра и в процент не идёт — иначе в ноябре у отличника выходило бы 45 % |
| Мобильный журнал | Таблица «студенты × задания» с закреплённой колонкой ФИО листается вбок. Для телефона главный путь — экран одного задания: список студентов и поле балла, сохранение без кнопки (HTMX по `change`) |

## Безопасность

- Роль `teacher`, связь учётки с преподавателем — `users.teacher_id`. Все роуты под `/t`
  отвечают 404 всем, кроме преподавателей.
- Каждая функция `app/grades/service.py` получает `teacher_id` или `student_id` **из сессии**
  (`Viewer.teacher_id` / `Viewer.student_id`) и фильтрует по нему в SQL. Курс, задание и студент
  из формы проверяются вместе: задание должно принадлежать курсу, курс — преподавателю,
  студент — быть записан в ведомость. Иначе 404, ничего не записывается. Тесты:
  `tests/test_grades.py` (чужой курс, чужое задание в своём курсе, студент не из ведомости,
  другой преподаватель, студент на страницах преподавателя).
- POST — с CSRF (поле формы или заголовок HTMX), как во всём кабинете.
- Сгенерированные студенты получают учётку со случайным паролем, который нигде не
  сохраняется (только argon2-хэш). Войти в них нельзя; для демо — student1/student2.

## Генератор данных

`python -m app.generate` (после `python -m app.seed`): по умолчанию 3000 студентов по 12 в
группах, у которых есть расписание; детерминированно от `--seed`; группа, где уже есть
сгенерированные студенты, пропускается. У каждого студента свой «уровень» (нормальное
распределение), у курса — «сложность»; из них баллы с шумом, редкие несдачи, пересдачи и
долги. Демо-учётки: student1 — сильная зачётка без долгов, student2 — средняя и один долг.
В конце создаются `teacher1` и `teacher2`: преподаватели, у которых больше всего ведомостей
в группах student1 и student2.

## Допущения

- Шкала и пороги — типичные для российских вузов, не регламент МГИМО.
- Часы и ЗЕ курса текущего семестра оценены по числу занятий в РУЗ.
- Кабинет преподавателя не даёт создавать курсы и менять состав групп — это делает деканат
  (в рабочей версии — учебный план из 1С).
