# Классы MGIMO-LMS: три представления

Дата: 16 ноября 2026. Основа — текущая рабочая копия, включая локальные изменения.
Это документация и предложения для обсуждения, а не решение о рефакторинге.

## С чего начать

1. [Предметная модель](01-domain.md): какие сущности есть в системе и что с ними делают.
2. [Текущее устройство кода](02-current-code.md): где действительно находятся данные и поведение.
3. [Учебная ООП-модель](03-oop-proposal.md): как можно распределить часть поведения между объектами.

**Класс** — описание структуры и поведения. **Объект** — конкретный экземпляр класса.
Например, Student — класс, а профиль вымышленного студента с id=101 — объект.
**Переменная** student может ссылаться на этот объект. **Атрибут** student.full_name хранит имя.
**Свойство** Python с @property вычисляется при обращении, например course.is_closed
в предложенной учебной модели. **Метод** вызывается у объекта: course.close(at)
в той же модели. **Функция** вызывается отдельно:
close_course(db, teacher_id, course_id). В текущем проекте большая часть действий — функции сервисов.

SQLAlchemy ORM связывает Python-классы с таблицами БД. Pydantic-классы описывают и проверяют
формат данных; dataclass удобен для передачи данных. Наличие class не делает сущность таблицей.

| Представление | Вопрос | Пример |
| --- | --- | --- |
| Предметное | Что делает студент? | Заказывает справку |
| Текущее устройство | Как это реализовано? | Student хранит профиль; create_request создаёт заявку |
| Учебное ООП | Где можно разместить правило? | CertificateRequest.can_download(now) проверяет состояние объекта |

Метки: **[ЕСТЬ]** — найдено в рабочем коде; **[В СЕРВИСЕ]** — действие реализовано вне
сущности; **[ПРЕДЛОЖЕНИЕ]** — новое поле, метод либо класс, ещё не реализованный.
Концептуальное имя операции не является обещанием существования одноимённого Python-метода.

В UML `+` означает публичный член; `-` — закрытый член в проектируемом интерфейсе.
Python не обеспечивает строгую приватность одного подчёркивания. `0..1` — необязательная
связь с одним объектом, `1` — ровно один, `0..*` — любое количество.
Стрелка `..>` — зависимость, линия `--` — связь, `..|>` — реализация интерфейса.
`/поле` — вычисляемое значение, не новая колонка БД. `?` в пояснениях — допустимо None.

Схемы Mermaid показывают ключевые поля, а полный перечень текущих полей находится в каталоге
предметной модели. Первоначальная работа ограничивалась документацией. Затем по запросу
пользователя реализована [загрузка документов работником](../staff-document-upload.md):
добавлены ORM-модель, миграция, серверный сервис и экран. Остальные предложения не реализованы.
Для простых записей связей отсутствие методов допустимо: не нужно придумывать действие каждой таблице.
